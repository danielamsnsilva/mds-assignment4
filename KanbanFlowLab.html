Kanban is a strategy for optimizing the flow of value. Work is made visible on a board, the amount of is limited, and new work is only when there is capacity for it.

The three Kanban practices

01
Define and visualize the workflow

Make work items, start and finish points, states, WIP control, policies, and a service level expectation (SLE) explicit.

02
Actively manage items

Control WIP, unblock work, and act on items that are ageing or approaching their SLE.

03
Improve the workflow

Use flow data to adapt how work is done and improve effectiveness, efficiency, and predictability.

Reading a CFD. The vertical distance across the "in progress" band is WIP. The horizontal distance is approximate cycle time. The slope of the Done band is throughput. A band that keeps widening means work is entering faster than it leaves.
Lead time = WIP / Throughput
{{ law.ct }}days average cycle time

One of Kanban’s strengths is WIP limits, setting caps on how much work can be in each stage. Using Little’s Law, you can calculate how much WIP your system can handle if you want to maintain a specific lead time: WIP = Lead Time × Throughput
